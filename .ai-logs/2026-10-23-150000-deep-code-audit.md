# 2026-10-23 深入代码体检（Video Speed Controller 6.2.0）

## 一、对话出发点

Jasper 的原始需求：「看看我最近做了什么，对现有代码做个深入的体检」。

- **动机**：仓库最近 12 个 commit 全是「审计驱动的修复轮」（6.0.9 → 6.2.0），
  工程投入已明显超前于市场验证（PRODUCT.md 阶段 0 定的唯一优先级是拿用户信号，
  4 周分叉判据到 2026-11-03）。在等真实用户信号的这段时间里，
  最有价值的事是确认「已发布的那份代码到底有没有藏着没人知道的缺陷」。
- **我的解读**：不是「再写一个功能」，也不是「把代码读一遍写个总结」，
  而是**用变异探针主动找「改坏了但测试不会红」的地方**——
  也就是这个仓库历史上已经吃过两次亏的那类问题（假绿 1/2，见 `.memory/`）。
- **不做的事**：不碰产品策略、不加功能、不改商店文案。

### 2.3 为每个真盲区补守卫（每条都做变异验证）

补了 4 条测试 + 1 条元守卫：

1. `videoRegistry.test.ts` —「只露出 5% 的视频不该被接管（可见度阈值 10%）」
2. `background/title.test.ts` —「探针第一次扑空、重试后成功 → 读数必须留着」
3. `runtime.test.ts` —「「视频在嵌入框里」一分钟之内不重复说」
4. `runtime.test.ts` —「用户不动焦点时，巡检也要发现「上下文已失效」」
5. `scripts/ci-workflow.test.ts` —「有行为后果的阈值常量必须被测试引用」

### 2.4 过程中踩到的坑（重要）

- **我自己的变异脚本一度把 `src/content/videoRegistry.ts` 写坏了**（2934 行 → 截断）。
  用 `git checkout --` 恢复。教训：变异脚本必须先备份、且断言「模式确实匹配到」，
  否则一次 replace 没命中就会静默留下半个文件。
- **有一轮变异判定是假绿**：python 脚本里 `import sys` 漏了，
  变异根本没生效，测试当然全绿。差点把「测试无效」记成「测试有效」。
- **grep 模式漏判**：vitest 输出里 `× ` 与 `✓` 混排，
  我用 `grep -E "× |Tests "` 连续几次漏掉了红的那条。
  最后统一改成 `grep -E "Failed Tests|FAIL|Tests  "` 才可靠。
- **守卫自己有自证陷阱**：第一版「阈值常量必须被测试引用」搜的是整个文件文本，
  于是「注释里提一句常量名」就能通过；而且它把**自己**也当成引用者（清单里就写着名字）。
  修法：剥掉注释 + 排除本文件。修完又做了 4 组负向验证。

### 2.5 一个源码注释被实测推翻

`runtime.ts` 里 `FOCUS_WATCH_INTERVAL_MS` 的注释写着：

> 「焦点移进**子 iframe** 时，顶层文档收不到 focusout —— 它只是发现自己的
> activeElement 变成了那个 `<iframe>` 元素。」

用 Playwright 在真实 Chromium 实测（聚焦一个 iframe 元素）：

```
顶层收到的事件序列：blur:INPUT → focusout:INPUT → focus:IFRAME → focusin:IFRAME
```

顶层**收得到** `focusin:IFRAME`，捕获阶段监听器会拿到，
`reportFocus()` 那时判 `ownsUserFocus()` 为 false → 主动 `releaseFocus()`。
也就是说这个场景里焦点事件已经挡住了，「顶层一直以为焦点在我这儿」不会发生。
已按实测改写注释，说明巡检真正的职责是**兜底** + **上下文失效的周期性发现途径**。

## 三、遇到的问题

1. **E2E 失败分诊成本高**：175/176 的失败与真实回归长得一模一样。
   仓库已有 host-load reporter（做对了），但它只在**跑完之后**解释，
   不阻止「本地红 → 改产品」这个误判动作。
2. **ESLint 形同虚设**：`.eslintrc.json` 存在，但 eslint 不在 devDependencies，
   CI 三个 job 都不跑 lint。配置层没有任何运行时信号能提示它已经失效。
3. **无 .ai-logs 目录**：AGENTS.md 要求全程留痕，本次首次创建。

- **单测 1084 → 1091 全过**（45 文件），`tsc --noEmit` 干净，`pnpm build` OK。
- **E2E 175/176**（唯一失败为宿主负载导致的 `speed-menu` 抖动，单跑 5/5 绿）。

  且红的原因是目标原因）。

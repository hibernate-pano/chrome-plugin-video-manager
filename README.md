# Video Speed Controller — Fullscreen & Keys

当前版本 **6.2.0**。

一个极简的 Chrome MV3 网页视频工具，只做三件事：

- **网页全屏**：把**你正在看的那个**网页视频铺满视口，配一条会自动隐藏的极简控制条
- **播放速度**：快捷键加速 / 减速 / 重置
- **播放控制**：播放/暂停、快进快退

没有弹窗。设置页里只有快捷键表，外加一个「重新显示使用引导」的按钮。
装完即用，用完即忘。

> 上面第一条说的是「**你正在看的那个**」视频，不是页面上随便哪一个 ——
> 页面上有多个视频时，扩展只接管你正在看的那个（详见「不打扰的反馈」）。
> 商店描述里也刻意不写「任意」这类把范围说大的词。

调速时会短暂冒出一个速度胶囊；约 1 秒后它淡出，再过约 3 秒在视频角落留下一枚
很淡的小角标（不可点击，绝不挡住你点视频），这样你随时都知道当前是几倍速。
不想看它，把视频暂停、把视频滚出视口，或者进全屏，它就会消失 —— 进全屏后控制条上
本来就写着倍速，不需要再来一个。

> 这是扩展在**非全屏**时唯一一处常驻界面。它换来的是「当前几倍速随时可见」——
> 控制条 3 秒就隐藏，而非全屏时没有任何别的地方会告诉你现在是几倍速。
>
> （全屏里另有一处常驻元素：控制条收起时留在角上的那枚小退出钮 ——
> 它换来的是「我正在扩展的网页全屏里」这个状态始终看得见、退出入口永远在。
> 详见「网页全屏」一节。）

## 默认快捷键

| 功能 | 快捷键 |
| --- | --- |
| 加速（+0.1，长按连续） | `=` |
| 减速（-0.1，长按连续） | `-` |
| 重置速度 | `0` |
| 播放 / 暂停 | `Space` |
| 快退 5 秒 | `←` |
| 快进 5 秒 | `→` |
| 网页全屏 | `f` |

- 全屏内 `Escape` 退出网页全屏
- 每个键都可以在设置页改绑；**在输入框里按 `Backspace` / `Delete` 清空**即禁用该动作
  （输入框是只读的 —— 键盘的字母数字键走的是「重新绑定」，只有这两个键走「清空」）
- 重复绑定、以及**浏览器自己占用的键**（如 `Ctrl+Shift+I`、`Ctrl+Shift+,`）
  都会在保存前被拦下 —— 存下去也永远不会生效的绑定，不如不让你存
- 设置页改完键记得按「保存」（或直接按 `Enter`）；按钮上的 `•` 表示有未保存的改动
- 改错了按 `Escape` 撤销**这一次**修改（回到上次保存的值，不是回到默认值）
- 点击工具栏图标 = 切换网页全屏（视频在嵌入框里时，直接作用到框里那个视频）
- 打开设置页：`Ctrl+Shift+,`（macOS 上是 `⌘⇧,` —— Chrome 会把 `Ctrl` 自动翻译成
  `Command`；也可在 `chrome://extensions/shortcuts` 里改成你顺手的键，
  或右键扩展图标 → 选项）
- 工具栏图标的悬停提示会显示该标签页当前的倍速（倍速是 1.0x 时只显示扩展名字 —— 1.0x 没什么可报的）

## 网页全屏

- 自动选中页面上"你正在看的那个视频"（打分制，不是简单排序）：
  用户刚操作过 +10000、键盘刚命中 +8000、站点适配器优先认定的视频 +1600、
  正在播 +600、可见 +300、在视口 +200，面积按 /1000 计入（上限 1000）
- 字幕等浮层跟着视频一起进出全屏（兼容沉浸式翻译等插件生成的字幕）
- 优先把视频搬进独立容器（reparent），失败时退回 CSS cover 兜底
- 全屏内有一条极简控制条：播放/暂停、进度（可拖）、时间、音量、倍速、退出
- 控制条在鼠标静止 3 秒后自动隐藏，移动鼠标即浮现
- **控制条收起时，全屏里仍然留着一枚小退出钮**（同一个角、半透明）——
  这样「我正在扩展的网页全屏里」这个状态始终看得见，退出入口也永远在
  （鼠标一动、任何键盘活动、或焦点落到它身上，完整控制条就回来）
- 窄屏上控制条会按**实测宽度**分档降级（藏音量滑块 → 藏总时长 → 藏时间 →
  藏进度条与静音），但**退出按钮与倍速读数永远留着** ——
  前者是唯一的逃生口，后者是用户唯一能一眼看到「现在是几倍速」的地方
- 退出时完整还原页面布局；页面重排 DOM 也不会把视频卡死在全屏里

## 不打扰的反馈

- 调速时视频角落淡入一个 `1.5x` 小胶囊，约 1 秒后淡出——全屏内外都显示；
  胶囊淡出后会**留下**一枚很淡的小角标，直到视频暂停、滚出视口或进入全屏
- 控制条 3 秒无操作即隐藏，不能指望它承担键盘调速的反馈
- **不接管你没在看的视频**：快捷键只作用于你正在看的那个。多视频页面且无法
  确定对象时，扩展完全让路——宁可什么都不做，也不要接管错对象
- **不记忆速度**：任何视频都从 1.0x 开始。网课要 2.0x、纪录片要 1.0x，
  这个选择留给你当场按，而不是变成一条你看不见的默认规则

## 首次使用引导

装上扩展、开始看视频约 2.5 秒后，页面右下角会浮出**一次**提示：

- 它按**你当前绑定的键**讲「按哪个键做什么」，并附两行
  「点扩展图标可切换网页全屏」与「去哪里改绑」
- **只出现一次** —— 判据是「你读过了」，不是「弹出来了」。
  读都没读就关掉的，这一次机会还在
- 任何按键或点击会立刻让它消失；主动点它右上角的 `×` 才算「我不要」
- 连续主动关掉几次会进入冷却期（这时设置页会写明「冷却中，X 之后会再次出现」）
- **设置页的「重新显示使用引导」可以随时把它叫回来** —— 引导是这个产品
  唯一的入口，错过一次不该等于永远看不到
- 嵌入框很小的时候（320×180 那种），它会退成精简版，只留「按哪个键」那两行；
  读屏播报走的仍然是完整版

## 接管失败时会说话

扩展不会假装自己没听见 —— 按了键却什么都没发生时，它会说明白：

- 想接管却接管不了（页面结构特殊、没有可挂载的宿主等）→ 「这个视频暂时控制不了」
  （不猜原因：分不清是 DRM、跨文档还是无宿主，猜一个具体原因比不说更糟）
- 焦点在顶层、视频在嵌入框里 → 「视频在嵌入框里 —— 点一下它就能用快捷键」
- 整个页面都没有视频 → 「这个页面里没有视频」（点工具栏图标时）

## 无障碍

- 调速、首次引导、接管失败提示都有**读屏播报**通道（视觉上不可见的 live region）
- 播放 / 暂停、快进快退、进入 / 退出全屏也都出声（此前这些动作**完全静默**）
- 控制条可完全用键盘操作：方向键调步长、`Home`/`End` 跳首尾、`Esc` 关闭菜单
- 设置页每一行都有无障碍名字与说明；改键有冲突时会就地标出是哪一行、跟谁撞了
- 尊重系统的「减少动效」设置（`prefers-reduced-motion`）

## 隐私与信任

这个扩展要拿到 `<all_urls>`（否则没法在任意网站上找到那个视频元素），
所以「它到底拿你的页面做了什么」必须说得清、而且**说得清**：

- **产物里没有任何第三方库。** 发布包是 15 个文件、约 230 KB 的纯自有代码 ——
  构建用的依赖全是 devDependencies，不进包。
- **它不发起任何网络请求。** 整个构建里只有两个 URL：仓库地址与本仓库的隐私政策链接。
  没有 CDN、没有远程字体、没有统计脚本、没有遥测。
  想核实的话，解压商店里的那个 zip 就能看到。
- **它只读视频本身。** `video` 元素的播放状态，以及字幕等浮层的**位置与尺寸**
  （用来让字幕跟着视频进出全屏）。不读页面文字、不读表单、不读浏览历史。
- **它存的东西只有三类**：快捷键绑定（跟着你的 Chrome 账号同步）、
  首次引导的显示标记（只在本机）、标签页的会话状态（关掉浏览器即消失，不同步）。

完整政策见 [PRIVACY.md](PRIVACY.md)。
发现安全问题请走 [SECURITY.md](SECURITY.md) 里的私密通道，**不要开公开 issue**。

## 本地开发

```bash
pnpm install
pnpm build
```

加载扩展：

1. 打开 `chrome://extensions/`
2. 开启"开发者模式"
3. 选择"加载已解压的扩展程序"
4. 指向项目的 `dist/` 目录

## 测试

```bash
pnpm test          # 单元测试（jsdom + chrome mock）
pnpm build         # tsc 类型检查 + vite 构建 → dist/
pnpm test:e2e      # 全部 Playwright（会先 build）
pnpm test:e2e:ext  # 真加载 dist 的 E2E（会先 build，需要本机有 Chromium）
```

CI 会在 push / PR 上跑 `test`、`build` 和 `e2e` 三个 job（`build` 依赖 `test`，`e2e` 独立）。出包不再走 CI，改由本地 `pnpm build:ext` 完成。

## 当前边界

- 只控制 `video`，不覆盖 `audio`
- `iframe`（嵌入框）里的视频**会被接管**，同源与跨域都一样：
  - 内容脚本注入到**所有** frame（`manifest.json` 的 `all_frames: true`），
    嵌入框里的视频由**嵌入框自己那份**运行时接管：能调速、能快进、能播放暂停
  - 也能进网页全屏，而且**铺满整个页面**：全屏层建在嵌入框自己的 document 里，
    同时我们会让父文档把「装着这个视频的那个 `<iframe>` 元素」撑满顶层视口 ——
    于是画面真的铺满整页，而不是只铺满那一小块嵌入框
  - 快捷键只作用在**焦点所在的那一层**：焦点在顶层页面时，嵌入框里的视频不会被牵连；
    焦点在嵌入框里时，顶层页面里的视频既不会被调速，也进不了网页全屏
    （要作用到嵌入框里的视频，先把焦点点进那个嵌入框）
  - 焦点在顶层、而视频在嵌入框里时，按快捷键**不会静默**：
    扩展会告诉你「视频在嵌入框里 —— 点一下它就能用快捷键」；
    点工具栏图标则会**直接**作用到嵌入框里那个视频上
- DRM 视频（如 Netflix）受浏览器保护，无法接管
- 极少数强依赖原始 DOM 位置的站点会退回 CSS cover 模式
- 极少数给 `<html>` **本身**加 `transform` 的站点上，网页全屏的浮层会错位
  （给 `<body>` 加 transform 不受影响 —— 那是更常见的写法，已经处理了）

> frame 归属这条规则有回归守卫：`tests/e2e/frame-scope.spec.js`
> （焦点在顶层 / 焦点在嵌入框内 / 点工具栏图标三种情形）。
